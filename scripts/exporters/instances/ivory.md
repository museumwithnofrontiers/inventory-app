# Ivory (instance ivory)

The package `@museumwnf/ivory-data` is produced by
[`dxa-gallery`](../dxa-gallery/README.md) from
[`ivory.json`](ivory.json) next to this file — see
[`../docs/dxa-gallery-data-package.md`](../docs/dxa-gallery-data-package.md)
for the package specification and
[`../dxa-gallery/NPM_PUBLISH.md`](../dxa-gallery/NPM_PUBLISH.md) for the
publish mechanics. This note keeps everything specific to this site: legacy
scope, membership reasoning, decisions and known gaps.

It replaces one legacy deployment of `dxa-api` + `dxa-client`:
<https://ivory.museumwnf.org> (`thg_gallery` 20, legacy `link` `ivory`,
mwnf3 project `IVO`). Ivory is the first gallery of
[M5 wave 3](https://github.com/museumwithnofrontiers/inventory-app/issues/1739)
(ivory, jewellery, landscapes, leatherworks, manuscripts, metalwork, in
legacy-gallery-id order), generated by the same
[new-website recipe](../../../docs/deployment/new-website.md) steps 1–2 that
[`coins-medals`](coins-medals.md) exercised end to end first. Exported
through the same shared `dxa-gallery` exporter as every other gallery site.

## Numbers, from the staging export (2026-09-21, `--base-url
https://inventory.metanull.eu`)

- **56 member items, none of them native.** `IVO` itself carries no objects
  — a curatorial-only project, the same shape as
  [`coins-medals`](coins-medals.md) and [`amulets`](amulets.md) rather than
  [`carpets`](carpets.md). Read from `items.json` `project_id` against
  `manifest.json`'s `projects` map:
  - 32 from **Discover Islamic Art** (`ISL`)
  - 15 from **Explore Islamic Art Collections** (`EPM`)
  - 4 from **Sharing History** (`awe`)
  - 4 from **Discover Baroque Art** (`BAR`)
  - 1 from **Discover Carpet Art** (`DCA`)
- **Languages: 4 site languages (ar/en/es/fr), 9 languages overall**
  (`languages.json`). Item translations exist in all 9
  (`translations/items.{ar,de,el,en,es,fr,it,pt,tr}.json`) — no missing
  language row for these 56 items.
- **`gallery.json`: `featured: false`, `hidden: false`.** The live
  `/api/v2/thg/galleries/self` (fetched 2026-09-21, one call) answers
  `featured: true`, `hidden: false` — the same polarity mismatch documented
  on [`carpets`](carpets.md#the-one-field-where-the-package-deliberately-differs-from-the-live-api),
  [`amulets`](amulets.md) and [`coins-medals`](coins-medals.md#numbers-from-the-staging-export-2026-09-21---base-url-httpsinventorymetanulleu):
  the package ships the documented meaning of `featured`. `hasTimeline` /
  `hasCountryBasedTimeline` both `false` on the live endpoint, matching
  `has_timeline` / `has_country_timeline` in `gallery.json`.
- **37 timelines, 26 countries, 1,390 events** in `timelines.json` /
  `timeline_events.json` — the same corrected totals as every other DXA
  gallery site so far; nothing gallery-specific about the timeline here.
- **31 countries** in `countries.json`. Verified directly: item countries
  (18) ∪ partner countries (18) ∪ timeline countries (26) = 31, the exact
  `countries.json` count.
- **33 partners**, 14 `featured`, 0 with `item_count: 0` — the MWNF-384
  "museum created under the gallery's own project but holding nothing"
  branch is present in the exporter but inert here, as on every gallery site
  so far: no partner ships with `item_count: 0`.
- **112 tags** (artist 4, dynasty 13, material 42, subject 14, type 39), **11
  dynasties**, **90 glossary entries**.

## Slug vs. legacy link

No mismatch here: the site slug is `ivory`, the npm package
`@museumwnf/ivory-data`, and `gallery.json` carries `slug: "ivory"`
(`thg_gallery.link`) — the same value, like `carpets` and unlike
`coins-medals`/`amulets`.

## Known gaps

Verified during this export, none blocking:

- **15 items have an empty English (`en`) description**, out of 56
  (`translations/items.en.json` against `items.json`). All 15 are from the
  `EPM` (Explore Islamic Art Collections) source project — the same,
  already-documented importer-side gap as on carpets, amulets and
  coins-medals: legacy keeps the short text in `objects.description2`, which
  the importer files as the EPM-context translation, so an EPM-native
  record's only row is that short one and its long description is
  legitimately empty. Unlike coins-medals, no outlier from another source
  project here — the pattern is clean.
- **No item is missing an English title.** All 56 items resolve a non-empty
  `name` in `translations/items.en.json`.
- **EPM author attribution** — same importer-side gap as carpets/amulets/
  coins-medals: `preparedBy`/`copyEditedBy` file only onto the Arabic row for
  EPM items, so `author`/`copy_editor` are absent from the English
  translation of an EPM-sourced record here too. Not re-verified item by
  item on this site; recorded because the same 15 EPM-sourced items above
  are the likely carriers.
- **`notice` and `notice_c`** are not imported, per the standing rule
  documented on carpets/amulets/coins-medals; not specifically re-checked
  here.
