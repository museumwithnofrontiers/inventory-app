# Coins and Medals (instance coins-medals)

The package `@museumwnf/coins-medals-data` is produced by
[`dxa-gallery`](../dxa-gallery/README.md) from
[`coins-medals.json`](coins-medals.json) next to this file — see
[`../docs/dxa-gallery-data-package.md`](../docs/dxa-gallery-data-package.md)
for the package specification and
[`../dxa-gallery/NPM_PUBLISH.md`](../dxa-gallery/NPM_PUBLISH.md) for the
publish mechanics. This note keeps everything specific to this site: legacy
scope, membership reasoning, decisions and known gaps.

It replaces one legacy deployment of `dxa-api` + `dxa-client`:
<https://coins-medals.museumwnf.org> (`thg_gallery` 13, legacy `link`
`coins_and_medals`, mwnf3 project `COI`). Coins and Medals is the first
gallery generated by the [new-website recipe](../../../docs/deployment/new-website.md)
end to end ([story #1930](https://github.com/museumwithnofrontiers/inventory-app/issues/1930),
epic [#1737](https://github.com/museumwithnofrontiers/inventory-app/issues/1737)),
moved up from wave 2 ([#1738](https://github.com/museumwithnofrontiers/inventory-app/issues/1738))
by Pascal on 2026-09-21 to exercise the M4 tooling
([`dxa-gallery`](../dxa-gallery/README.md), the instance-file mechanism, the
lookup command) on a real site before wave 1 runs at scale. It is exported
through the same shared `dxa-gallery` exporter as every other gallery site —
there is no fork for this one, unlike the original `carpets`/`amulets` pair.

## Numbers, from the staging export (2026-09-21, `--base-url
https://inventory.metanull.eu`)

- **100 member items, none of them native.** Every one is borrowed, the same
  shape as [`amulets`](amulets.md) (45 items, all borrowed) rather than
  [`carpets`](carpets.md) (486 items, 398 native). `COI` itself carries no
  objects — it is a curatorial-only project, like `AMU` — so the membership
  union (items of the gallery's own project OR items listed in the
  `thg_gallery_*` link tables) resolves entirely to the second half here.
  Read from `items.json` `project_id` against `manifest.json`'s `projects`
  map:
  - 56 from **Sharing History** (project key `awe`, per the memory of decision
    "AWE single project, lowercase keyspace")
  - 20 from **Discover Islamic Art** (`ISL`)
  - 13 from **Explore Islamic Art Collections** (`EPM`)
  - 9 from **The Hijaz Railway** (a project with no `site_url`/
    `related_database_url` in `manifest.json` — a sub-collection exported the
    same way as any other source project, not a special case)
  - 2 from **MWNF Galleries** (the cross-gallery curatorial project)
- **Languages: 4 site languages (ar/en/es/fr), 8 languages overall**
  (`languages.json`). The extra four (de/it/pt/tr) are carried by borrowed
  records from source projects that hold text in those languages; the site
  itself displays only ar/en/es/fr, matching the collection languages
  resolved in step 1. Item translations exist in 6 of the 8
  (`translations/items.{ar,de,en,es,fr,it}.json` — no `pt` or `tr` row for
  any of these 100 items specifically).
- **`gallery.json`: `featured: false`, `hidden: false`.** The live
  `/thg/galleries/self` (fetched 2026-09-21, one call) answers
  `featured: true`, `hidden: false` — the same polarity mismatch documented
  on [`carpets`](carpets.md#the-one-field-where-the-package-deliberately-differs-from-the-live-api)
  and [`amulets`](amulets.md), confirmed here directly: `dxa-api` copies the
  `hidden` projection into `featured` without flipping it
  (`isFeatured` in
  [`../dxa-gallery/src/exporters/gallery-exporter.ts`](../dxa-gallery/src/exporters/gallery-exporter.ts)),
  so a record stored `featured = 'H'` (the default, same direction as
  amulets) reads back `true` on the live site. The package ships the
  documented meaning. `hasTimeline`/`hasCountryBasedTimeline` both `false`
  on the live endpoint, matching `has_timeline`/`has_country_timeline` in
  `gallery.json`.
- **37 timelines, 26 countries, 1,390 events** in `timelines.json` /
  `timeline_events.json` — the same corrected totals as carpets and amulets,
  confirming the global-timeline merge (`mwnf3:hcr:country:*` plus
  `mwnf3_sharing_history:sh_hcr:*:exhibition:2`, documented on those two
  sites) applies unchanged to this instance; nothing gallery-specific about
  the timeline here.
- **30 countries** in `countries.json`. Verified directly: item countries
  (20) ∪ partner countries (20) ∪ timeline countries (26) = 30, the exact
  `countries.json` count — the timeline-coverage rule from carpets/amulets
  holds here too.
- **37 partners**, 10 `featured`, 0 with `item_count: 0` — the MWNF-384
  "museum created under the gallery's own project but holding nothing"
  branch is present in the exporter but inert on this site, the same way it
  is inert on amulets: no `mwnf3.museums` row has `project_id = 'COI'`.
- **74 tags** (artist 11, dynasty 18, material 19, subject 2, type 24), **18
  dynasties**, **77 glossary entries**.

## Slug vs. legacy link

The site slug is `coins-medals` (kebab-case, per decision Q4), the npm
package `@museumwnf/coins-medals-data`. `gallery.json` carries the legacy
value verbatim: `slug: "coins_and_medals"` (`thg_gallery.link`) — data values
keep legacy identity as-is, the site slug does not derive from it. Same
pattern as amulets (`amulets` vs. legacy `amulets_and_talismans`), not like
carpets where the two happen to coincide.

## Known gaps

Verified during this export, none blocking:

- **15 items have an empty English (`en`) description**, out of 100
  (`translations/items.en.json` against `items.json`). 13 of them are from
  the `EPM` (Explore Islamic Art Collections) source project — the same,
  already-documented importer-side gap as on carpets and amulets: legacy
  keeps the short text in `objects.description2`, which the importer files
  as the EPM-context translation, so an EPM-native record's only row is that
  short one and its long description is legitimately empty. The other 2 are
  from `GalEx5` (The Hijaz Railway); this project's connection to the EPM
  short-description rule was not established during this export, so it is
  recorded here as an open question rather than an explained pattern: item
  ids `2289c6e4-0334-5118-bc50-d1bec36ed791` and
  `de79e1c8-f7fb-5e5c-8cba-6385718388c1`.
- **No item is missing an English title.** All 100 items resolve a non-empty
  `name` in `translations/items.en.json`.
- **EPM author attribution** — same importer-side gap as carpets/amulets:
  `preparedBy`/`copyEditedBy` file only onto the Arabic row for EPM items, so
  `author`/`copy_editor` are absent from the English translation of an
  EPM-sourced record here too. Not re-verified item by item on this site;
  recorded because the same 13 EPM-sourced items above are the likely
  carriers.
- **`notice` and `notice_c`** are not imported, per the standing rule
  documented on carpets/amulets; not specifically re-checked here.
- **The live legacy API counts fewer items than the package.** Legacy's
  `/api/v2/items/count` and `/api/v2/objects/count` both answer 93 where
  `items.json` holds 100 (read during the site's step 6 comparison,
  [coins-medals#4](https://github.com/museumwithnofrontiers/coins-medals/pull/4)).
  `/thg/galleries/self`, the one call step 2 uses, reports no count, so
  this only surfaced at step 6. The cause was not investigated; it is an
  open question for the gallery epic, not a blocker for this site.
